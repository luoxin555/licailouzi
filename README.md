## 五十七、删除借款后流水残留 / 余额对不上（v2026-11-20.57）

### 根因

借款类的收支流水是自动生成的（`locked: true`），但**删除来源记录时没人管它**：

1. `logCashFlow()` 写流水时 `ref.id` 恒为 `""`，流水根本不知道自己是哪条借款生的，事后无法定位；
2. 删除借出的按钮压根没有 `data-kind`，点了没反应；删除借入时又**反过来多记一条**「删除借入」，于是现金被扣了两次；
3. 结果：记录删了，流水还在，余额越删越偏。

### 改法

- `logCashFlow(kind, amount, account, date, note, refId)` 现在把来源 id 一起存进 `ref.id`；
- 新增 `removeCashFlows(kind, refId, name)`：按 `ref.kind + ref.id` 找出这条记录的全部自动流水，**逐条按反方向把现金退回**，再从 `cashLog` 里删掉；老数据没有 `ref.id` 时用备注前缀兜底；
- 删除确认弹窗改成「将删除「谁」，并一并撤掉它自动记的收支流水，现金按原路退回」；
- **不重复冲回**：撤流水时每条已经退过现金，所以只有一条流水都找不到（老数据）时才用本金兜底退一次；
- 借出卡片的编辑/删除按钮补上 `data-kind="loan"`，三类记录（借出 / 借入 / 项目款项）走同一套删除逻辑。

### 验证（`r57.js`，14 条全绿）

| 场景 | 断言 |
| --- | --- |
| 借出 1000 | 现金 −1000；生成 1 条锁定流水；`ref.id` = 借出记录 id |
| 删除借出 | 记录没了；流水没了；**现金回到放款前的原值** |
| 借入 2000 | 现金 +2000；流水方向为 `in` |
| 删除借入 | 记录没了；流水没了；现金回到原值（不再出现 −2000 的二次扣款） |

另含版本号与 div 配平检查。

**核对版本**：弹窗标题里的 `v2026-11-20.57`，以及 `sw.js` 的 `VERSION`。

## 七十四、总览「累计收益」口径（v2026-11-20.74）

**公式**：`累计收益 = 持仓浮动盈亏 + 已实现盈亏 + 定存已产生利息 + 借出已收利息`

加进去的（4 项）：

| 项目 | 口径 | 说明 |
| --- | --- | --- |
| 持仓浮动盈亏 | 市值 − 成本 | 只算**有价格**的持仓；一直取不到行情的持仓不参与，避免凭空 −100%。货币基金每天赚的钱已折成份额，不会重复加 |
| 已实现盈亏 | 卖出差价 + 现金分红 + 红利再投资分红 | 送股（bonus）只加份额、不加收益，避免无中生有 |
| 定存已产生利息 | 起存日 → 今天 | 权责发生制，**未到账也算**；提前支取按活期重算并封顶 |
| 借出已收利息 | 还款记录里 kind=interest 的合计 | 第七十四轮补上的漏项（原来只进总资产、没进收益） |

不加进去的：未收（应收）利息、定存未产生利息、对外投资分红与投资本金（只做记录）、借入/项目款项的利息（负债成本，不进收益）。

**收益率分母** = 持仓成本 + 定存本金 + 借出未还本金。

**修掉两处重复/漏计**：

1. **重复**：定存到期入账后，本金已进现金，原来 `totals()` 仍按 `principal` 再算一次（同一笔钱算两次）。现在 `maturedAt` 有值就跳过本金，但把已赚到的利息留在累计收益里。
2. **漏计**：借出已收利息原来没进累计收益，已补；同时把借出未还本金加进收益率分母。
3. **顺带修**：`normalize` 原来把定存的 `cashAccount / matureAccount / maturedAt` 丢掉——重开 App 后到期入账会退化成「入现金存款」，还能重复入账。已加入白名单。

**验证**：`r73.js`——浮动盈亏 200、已实现 0、定存应计 235、借出已收 300，累计收益 = 200+0+235+300；到期入账后本金归零、利息仍留在收益里、总资产只多出利息那 235。

**核对版本**：弹窗标题里的 `v2026-11-20.74`。

## 八十八、净值日为什么不往前走（v2026-11-20.88）

**结论**：净值日本来就按交易日推进，周末和节假日不会动。今天是 2026-11-23（周一）11:04，今天的净值要到晚上 19:00 后才公布，所以现在显示 2026-11-20（周五）是正确的，不是卡住了。实测 005455 最新净值日 2026-11-20、002750 也是 11-20；016778 是货币基金，万份收益连周末都发，净值日已经到 2026-11-22。

- **自动刷新的判据**：每 15 秒检查一次「有没有该更新但没更新」的持仓。基金在交易日 19:00 前、以及非交易日，应到日期是上一个交易日；19:00 后才是当天。所以白天打开看到周五的净值是对的。
- **修掉一个会让日期彻底停住的坑**：原来判断只看「净值日 < 应到日期」，如果净值日被手工填成未来日期（填错、或时区错乱），这个条件永远不成立，自动刷新就一直空转、日期再也不动。现在「没有净值日」和「净值日在未来」都会强制重新拉一次，自己修回来。
- **状态条说清楚为什么不动**：以前只写「已是最新净值」，容易让人以为坏了。现在直接写「净值日 11/20 已是最近一期 · 今日净值 19:00 后公布」。
- **要立刻补一次**：点持仓页的「刷新行情」，它不看上面那个日期门槛，会直接重拉（实测把 11-13 的持仓拉到了 11-20）。
- **验证**：`r88.js` 8/8（净值日等于应到日→不刷、落后→刷、空日期→刷、未来日期→刷、状态条含「净值日 11/23」与「19:00 后公布」、div 配平），单文件与 `site/index.html` 各跑一遍全绿。

## 九十三、已收利息不再重复计入总资产（v2026-11-20.93）

- **核对结论：确实重复算了一次。** 借出「收到利息」这条记录走的是 `cashDelta(+利息, 收款账户)`，钱已经进银行卡/微信/支付宝余额；而总资产公式里又写了 `+ loanReceived`（已收利息合计），同一笔钱被数了两遍。
- **改法**：`total = 持仓市值 + 定存本金 + 现金 + 借出未还本金`，删掉 `+ loanReceived`；资产分布里同步删掉单独那一行「利息」（金额本来就在「现金」里）。`totals().loanReceived` 仍照常返回，只用于概览「已付利息」这类展示。
- **当前口径（一行公式）**：总资产 = 基金/股票/黄金市值 + 定存本金 + 四个现金账户 + 借出未还本金；未收（应收）利息、投资本金与分红都不进；已收利息只通过现金账户体现，不再单列。
- 验证：`r93.js` 9/9（现金 5,300 含 300 已收利息、借出未还 10,000、总资产 15,300 而不是 15,600、分布无「利息」项），单文件与 `site/index.html` 各一遍全绿。

## 九十四、两张回款卡片 + 总资产全量去重核对（v2026-11-20.94）

### 2. 总资产逐项核对结果（当前公式）

`总资产 = 持仓市值 + 定存本金 + 四个现金账户 + 借出未还本金`

| 项目 | 是否进总资产 | 为什么不会重复 |
| --- | --- | --- |
| 基金/股票/黄金市值 | 进 | 只按市值计一次，买卖流水只改份额与成本 |
| 定存本金 | 进 | 存进去时现金已经减掉，本金加回，净额不变 |
| 现金四账户 | 进 | 是余额本身，其他项目都是它的来源或去向 |
| 借出未还本金 | 进 | 放款时现金减、借出加，净额不变 |
| 已收利息 | 不进（本轮之前是双算） | 收款时已 `cashDelta` 进现金，再单列一次就是重复（`.93` 已删） |
| 应收（未收）利息 | 不进 | 只是应收，没进任何账户 |
| 定存未产生利息 | 不进 | 未到账 |
| 对外投资本金 / 分红 | 不进 | 投出去的钱单独记，已在 `.91` 剔除 |
| 借入款 | 不进 | 是负债，放款入账进现金，不在资产侧再加一份 |
| 项目款项 | 只有已入账部分进（在现金里） | 未入账部分只是应收 |
| 银行卡 / 微信 / 支付宝 | 进（现金的四个组成部分） | `cashParts` 与 `bankCards` 以 `alignBankCards()` 对齐，不另加 |

结论：**除已收利息那一处（`.93` 已修）之外，没有第二处重复计算**；借出、定存、投资回款都满足「现金减少 ↔ 资产增加、净额不变」。

- 验证：`r94.js` 13/13（两张卡片文案与可点、两个弹窗能打开、总资产 = 市值+定存+现金+借出未还、已收利息只展示不进总资产），单文件与 `site/index.html` 各一遍全绿。
