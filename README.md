# 理财记账 · 部署与安装说明

这是一个可以装到 iPhone 桌面上的 PWA 版本：点开图标全屏运行，没有地址栏，和原生 App 一样；数据只存在手机浏览器本地，不上传任何服务器。

## 一、包里有什么

```
index.html              应用本体（单页，含全部逻辑与样式；约 206 KB）
manifest.webmanifest    PWA 清单（名称、图标、启动方式）
sw.js                   Service Worker（首屏离线缓存 + 更新策略）
icons/                  图标：192 / 512 / 1024 / maskable-512 / apple-touch-icon-180 / favicon-32
README.md               本文件
```

合计约 358 KB，不依赖任何 CDN、字体或第三方脚本。

## 二、为什么必须要一个网址

iOS 的「添加到主屏幕」只接受 http(s) 网址。Safari 打不开 `file://` 本地 HTML，从「文件」App 点开只是快速预览，没有「添加到主屏幕」这个入口。所以要让图标出现在桌面上，必须把这几份文件放到任意一个静态托管上（免费的就够了）。

托管方只提供页面文件，看不到你的持仓和金额——数据在你自己手机的 localStorage 里。「更新行情」时是手机直接连天天基金、东方财富、腾讯的公开接口，不经过托管方。

## 三、部署（任选一种，5 分钟内完成）

### 方式 A：GitHub Pages（免费、长期可用的推荐做法）

1. 登录 github.com，右上角 **+** → **New repository**
2. 仓库名随意，例如 `licai`；可见性选 **Public**；勾选 **Add a README file** → **Create repository**
3. 仓库页 → **Add file** → **Upload files** → 把本压缩包**解压后的全部内容**（`index.html`、`manifest.webmanifest`、`sw.js`、`icons` 文件夹）一起拖进去 → **Commit changes**
   - 关键：`index.html` 必须在仓库**根目录**，不要多套一层文件夹
4. 仓库页 → **Settings** → 左侧 **Pages** → Source 选 **Deploy from a branch**，Branch 选 **main**、目录选 **/(root)** → **Save**
5. 等 1 分钟左右，页面顶部会显示网址：`https://<你的用户名>.github.io/licai/`
6. 用 iPhone 的 Safari 打开这个网址

### 方式 B：Cloudflare Pages / Netlify Drop（拖拽即部署，不用 Git）

- **Netlify**：打开 `app.netlify.com/drop`，把解压后的文件夹直接拖进网页，几秒后得到 `https://xxx.netlify.app`
- **Cloudflare Pages**：登录 dash.cloudflare.com → **Workers & Pages** → **Create** → **Pages** → **Upload assets** → 拖入文件夹 → **Deploy site**，得到 `https://xxx.pages.dev`
- **Vercel**：`vercel.com/new` → 拖入文件夹 → Deploy

### 方式 C：自己的服务器（nginx 示例）

把文件放到 `/var/www/licai/`：

```nginx
server {
  listen 443 ssl;
  server_name licai.example.com;
  root /var/www/licai;
  index index.html;

  # Service Worker 不要长缓存，否则更新不生效
  location = /sw.js { add_header Cache-Control "no-cache"; }
  location = /manifest.webmanifest { types { } default_type application/manifest+json; }

  location / { try_files $uri $uri/ /index.html; }
}
```

三个要点：**必须 HTTPS**（Service Worker 只在 https 或 localhost 下工作）；`sw.js` 不设长缓存；`manifest.webmanifest` 的 MIME 用 `application/manifest+json`（部分 nginx 默认给 `application/octet-stream`，会导致清单读取失败）。

### 方式 D：只想先在电脑上看效果

```bash
cd 解压后的目录
python3 -m http.server 8765
```

电脑访问 `http://localhost:8765`；手机连同一 Wi-Fi 访问 `http://<电脑内网IP>:8765`。

注意：手机用 `http://192.168.x.x` 打开**不是安全上下文**，Service Worker 不会注册，离线缓存和完整的主屏幕体验都没有，只适合看界面。

## 四、在 Safari 里添加到主屏幕

1. 用 **Safari** 打开部署好的 https 网址（必须是 Safari，微信内置浏览器不行）
2. 点底部工具栏中间的**分享**按钮（方框 + 向上箭头）
3. 在弹出的列表里往下找 **「添加到主屏幕」**
4. 名称保持「理财记账」→ 右上角 **「添加」**
5. 回到桌面，会出现蓝紫渐变的 **¥** 图标；点开是全屏的，没有地址栏和工具栏

装好之后，App 的「设置 → 安装与离线」会显示 **已启用**，并提示「当前已在主屏幕 App 模式下运行」。

## 五、断网能不能用

**能（只要联网打开过一次）：**

- 打开 App、在 4 个 tab 之间切换
- 看持仓、成本价、市值、盈亏、定存到期日和已计利息
- 新增 / 修改 / 删除记录、卖出、改价、记分红送股（写 localStorage）
- 导出 JSON 备份、复制备份文本

**不能（需要网络）：**

- 「更新行情」「全部更新」「改价」里的自动取价 —— 会提示「当前离线，无法获取行情」，并保留上一次的价格和日期
- 「接口自检」会显示不可用

断网时页面顶部会出现一条橙色提示：**当前离线：行情无法刷新，记账、查看与导出照常可用**。

前提：Service Worker 需要联网成功加载一次才算装好。从没联网打开过，离线是打不开的。

## 六、打开密码（应用锁）

首次打开会自动弹出「设置打开密码」，也可以先用「暂不设置」，之后在「设置 → 应用锁」里开启。

- **支持格式**：4–32 位，只能包含数字和字母（`A-Z a-z 0-9`）。含空格、符号、中文会被拒绝。
- **解锁时机**：冷启动一定要求输入；切到后台超过设定时间（立即 / 30 秒 / 5 分钟 / 1 小时，默认 30 秒）再回来也会重新上锁。
- **连续错误**：第 5 次错误起开始等待 30 秒，之后每多错一次翻倍（60 秒、120 秒……最长 15 分钟）。等待时间写进本地存储，重开 App 也不会重置。
- **修改 / 关闭**：都在「设置 → 应用锁」里，两者都必须先验证当前密码。
- **密码怎么存的**：只保存 `PBKDF2-HMAC-SHA256`（随机 16 字节盐 + 15 万次迭代）的哈希，本地存储里没有明文；备份 JSON 里也不含密码哈希，导入别人的备份不会改掉本机密码。
- **忘记密码**：没有找回途径。锁屏上的「忘记密码？」会给出唯一办法——清空本机数据重来（需要手动输入「清空」两个字二次确认），数据无法恢复。
- **能力边界**：这是本机层面的门锁，能挡住拿到你手机随手点开的人；它挡不住能在电脑上直接读浏览器本地存储的人。**它不是加密**，数据本身仍是明文存在浏览器里。

> 加锁时主内容会被清空，DOM 里不留任何金额、持仓名称、银行名称；页面标题固定为「理财记账」，不含任何金额。

## 七、自动备份怎么触发、有什么限制

### 触发时机

只有两个时机，都发生在「应用正在运行」的时候：

1. **打开应用**：进入首页并解锁后立刻存一份快照（来源标记「打开应用」）。
2. **数据改动后**：每次新增/修改/删除持仓、买卖、改价、记分红、增删定存、改现金、切换计息基准，都会在写入本机后存一份（来源标记「数据改动」）。

去重与合并规则：内容与上一份完全一样就跳过；一分钟内的连续改动合并成同一份（按第一次生成的时间算），避免记一笔账冒出十几份快照。也可以在设置里点「立即备份一次」手动加一份。

### 为什么做不到「后台定时」

这是一个**纯静态单页应用**：没有服务器、没有常驻进程，浏览器把标签页或 PWA 关掉之后，页面里的 JavaScript 就完全停止执行，`setInterval` 不会跑。所以**不存在**「每天凌晨自动备份」这种能力——任何声称能这么做的纯前端页面，实际都是在页面打开时补做。

真正的定时备份需要一台一直开着的机器（服务器、NAS、或者云函数）去调用接口写文件，那已经超出「一个 HTML 文件」的范畴了。

### 限制清单

- 应用没打开的时候不会备份，这段时间内的数据变化不会留快照。
- 备份和账目一样存在浏览器的 localStorage 里，**没有加密、也没有上传**。清浏览器数据、卸载主屏幕 App、iOS 的「清除网站数据」都会一起清掉。
- 备份跟着域名走：换网址（比如从 GitHub Pages 换到自己的域名）后看不到旧网址下的备份，需要先在旧网址里「导出 JSON」再在新网址导入。
- 默认保留 10 份，可在设置里改成 5 / 20 / 50；总量超过 2 MB 时从最旧的开始丢。
- 点「清空全部数据」会**连自动备份一起删掉**（隐私优先），想留退路请先导出。

### 建议的手动导出频率

自动备份只能防「刚刚改错了想退回去」，防不了手机丢失、系统清理、换设备。所以建议：

- **每周一次**：设置 → 数据备份 →「导出 JSON」，存到「文件」App 或 iCloud 云盘。
- **每月一次**：把导出的 JSON 再复制一份到电脑或其他云盘（微信文件传输助手也行）。
- **每次大额变动之后**（比如新增一笔大额定存、卖出一大笔）：顺手导一次，成本只有两秒。

导出的文件名带日期（`理财记账-2026-11-18.json`），恢复时用「导入 JSON 文件」即可整体覆盖。

## 八、净值 / 行情自动刷新怎么工作

### 什么时候会去拉数据

1. **打开应用并解锁后**：立刻拉一次全部持仓（基金取最新净值，股票取最新价）。
2. **停留前台且处于交易时段**：按设置里的间隔自动刷新，默认 5 分钟，可改 1 / 5 / 15 / 30 分钟。
3. **回到前台**：切出去再切回来，立刻补拉一次，不用等下一个间隔。
4. **手动**：持仓页右上「刷新行情」，或设置里「立即刷新」。

### 什么时候不拉

- **切到后台**：定时器暂停，不请求、不耗流量。浏览器对后台标签页本来也会节流，这里直接停掉。
- **锁屏状态下**：应用锁生效期间完全不联网，避免锁屏还在后台拉数据。
- **非交易时段与节假日**：09:15 前、23:30 后、以及周末和法定节假日都不自动请求，界面直接显示最近一次有效净值并标注**净值日期**。
- **收盘后（15:05–23:30）**：净值是一份份陆续公布的，所以这段时间最少间隔 15 分钟，避免高频空跑。

交易日判断按北京时间（UTC+8），不受手机时区影响；内置 **2026 年** 的法定节假日表，没有内置的年份退回「只按周末判断」，并在状态栏里写明。

### 失败的时候是什么表现

| 情况 | 表现 |
| --- | --- |
| 断网 | 顶部出现橙色提示条；不发请求，账目数字**保持原样**，不会变成 0 |
| 接口超时 / 报错 | 该标的下方标红「自动失败（原因）· 保留 X 分钟前的值」，价格与市值用上一次的 |
| 返回 0 或非法数字 | 视为脏数据直接丢弃，同样保留上一次的值 |
| 只有一只失败 | 其他标的正常更新，互不影响；汇总提示「成功 N 个，失败 M 个」 |
| 长时间没更新成功 | 该标的打上「陈旧」标记，避免把旧值当实时 |

底部来源标签会写清楚三件事：数据是**自动**还是**手动**、**几分钟前**抓取的、**净值日期**是哪一天。所以看到「自动 · 5 分钟前 · 净值 2026-11-17」就知道这是 11-17 收盘后公布的那份净值。

### 显示的到底是哪一天

这是最容易看错的地方，规则固定成下面几条：

1. **日期取自接口本身，不是抓取时间。** 基金用 `FundNetDiagram` 返回的 `FSRQ`（净值日期）；股票用东方财富 `f86` 或腾讯 `arr[30]` 里的行情时间戳，换算成北京时间后再取日期。
2. **列表不是按接口顺序取的。** 接口返回的是升序（最早在前），应用会先按日期排序再取最新一条，不会拿到窗口里最旧的那条。
3. **当日净值通常 19:00 之后才公布。** 所以白天打开时，基金显示的必然是**上一个交易日**的净值——今天（11-18）上午看到「净值 2026-11-17」是**正确**的，11-17 就是最新已公布的一份。
4. **数据落后时会明说。** 如果到了 19:00 之后还没有当日净值，或者某只基金连续几天没更新，标签会补一句「今日净值未公布」或「落后 N 天」，不会只丢一个旧日期让你误以为是实时值。
5. **概览右上角显示的是数据日期，不是今天的日期。** 之前那里写的是当天日期，会和下面的净值日期打架，现在改成持仓里最新的那个净值 / 行情日期，鼠标悬停有说明。
6. **周末和节假日不会「回退一天」。** 日期是接口给的字符串直接透传，不做时区加减；交易日判断统一按北京时间（UTC+8），手机时区改成别的也不会错位。

## 九、分红与红利再投资怎么算

### 三种分红方式

| 方式 | 份额 | 持仓成本 | 现金 | 已实现盈亏 |
| --- | --- | --- | --- | --- |
| 现金分红 | 不变 | 不变 | + 分红金额 | + 分红金额 |
| 红利再投资 | + 金额 ÷ 折算价 | + 分红金额 | 不变 | + 分红金额 |
| 送转股 | + 送转份额 | 不变 | 不变 | 不变 |

红利再投资的成本价会变成 `(原成本 + 再投资金额) ÷ (原份额 + 新增份额)`。因为份额变多了，后面净值每涨一点，赚到的钱都比拿现金时多——这就是复利。

### 每份派息和分红总额两种录法

结果完全一样，只是入口不同：

- 按每份派息：填「每份派息（元/份）」和「除息日份额」，总额 = 每份派息 × 除息日份额。
- 按分红总额：直接填总额，每份派息留空。

除息日份额默认取当前持仓份额，历史分红（除息日之后又买卖过）可以手动改成当时的份额，金额才准。

### 折算价从哪来

1. **手动填**：知道当天净值就直接写。
2. **点「取除息日净值 / 收盘价」**：基金走 `FundNetDiagram` 找 `FSRQ` 等于除息日那一条；股票走 `push2his` 日 K 线取当日收盘价。
3. **除息日休市**（周末、节假日）：自动退到之前最近的一个交易日，并明确提示「该日休市，已按 11 月 13 日的 1.0721 折算」，不会静默用错价。
4. **留空又没网**：先退到当前价（记录里标「按当前价」），当前价为 0 再退到成本价（标「按成本价」），两个都没有就拒绝保存并提示「缺少折算价格」。
5. **货币基金**：净值恒为 1，取价直接填 1.0000。这类基金的 `DWJZ` 是万份收益（0.3～0.4 那种数），不能当净值用。

### 现金分红怎么转成份额

在分红记录里点某笔现金分红的「转为再投资」，指定折算日期和价格，确认后：

- 新增份额 = 分红金额 ÷ 折算价
- 持仓份额和持仓成本同步加上，现金余额扣回这笔钱
- 已实现盈亏不变（这笔分红本来就记过了，转换只是把「拿到现金」换成「拿到份额」）

### 复利贡献怎么算

`再投资复利贡献 = Σ 每笔再投资的新增份额 ×（当前价 − 该笔折算价）`

意思是「如果当时拿的是现金，就赚不到这部分」，它**已经包含在浮动盈亏里**，不是额外收益，页面上也这么写。近两年的数字按除息日在最近 24 个月内的再投资记录单独汇总。

### 一个必须说清楚的地方

记账**不会**自动把除息日的净值下调。真实市场里分红后净值会跌，这件事交给「自动刷新」去抓当天或次日的净值来体现。所以刚记完一笔分红时，总资产看起来会涨一截；等净值刷新到除息日之后，数字就回到正常水平了。

### 编辑与删除

每笔分红都能编辑和删除。删除会把金额、份额、成本、现金、已实现盈亏**全部回滚**到记这笔之前的状态。旧版本只有 `tx` 流水、没有新结构的持仓，第一次打开会自动迁移成「旧版记录（未入现金）」，同样可以编辑和删除。

## 十、页面为什么不给缩放

viewport 写死成：

```html
<meta name="viewport" content="width=device-width,initial-scale=1,minimum-scale=1,maximum-scale=1,user-scalable=no,viewport-fit=cover">
```

但光靠 `user-scalable=no` 不够——iOS Safari 在好几个版本里会忽略它。所以下面三层一起拦：

1. **CSS**：`html{touch-action:pan-x pan-y}`，只留上下左右平移，捏合和双击放大都关掉。
2. **事件**：`gesturestart / gesturechange / gestureend`（Safari 专有的捏合事件）、`touchstart / touchmove` 双指、`touchend` 双击、`dblclick`，全部 `preventDefault`。双击那一层只在**非交互元素**上拦，按钮、输入框、标签页连点不会吞掉第二下。
3. **运行时兜底**：`visualViewport` 一旦报告 `scale > 1.01`，就重写一次 viewport 把页面拉回 1 倍。

### 输入框为什么是 16px

iOS 在**字号小于 16px** 的输入框聚焦时会自动把页面放大。样式表最后一条 `input,select,textarea{font-size:16px!important}` 把所有控件（包括 JSON 粘贴框）抬到 16px，从源头避免聚焦缩放。

### 长按和选中

`-webkit-touch-callout:none` 关掉长按弹出的菜单，`body` 默认 `user-select:none`；输入框单独放开（`user-select:text`），粘贴、全选、光标定位都不受影响。

### 布局怎么固定的

- `overflow-x:hidden` + `overscroll-behavior:none`：页面不会被任何元素撑出横向滚动，也不会整页回弹。
- `text-size-adjust:100%`：关掉 iOS 横屏时自动放大字号（这是横竖屏切换错位的主要原因）。
- 总资产数字 `clamp(26px,8.6vw,38px)`，统计数字 `white-space:nowrap` + 省略号，位数多也不会挤破卡片。
- 网格/弹性子项统一 `min-width:0`，长代码、长基金名不会把列撑宽。
- 弹层高度 `max-height:92dvh`（`dvh` 跟随键盘变化），键盘弹出时底部按钮不会被顶出屏幕。

### 装成主屏幕图标之后

同一个 HTML、同一个 viewport、同一套事件，`display:standalone` 下行为完全一致。不存在「网页里能缩、装成图标又能缩」的差异——因为它本来就是同一份文件。

### 代价

关掉缩放，对需要放大看小字的用户不友好（WCAG 1.4.4 建议允许放大到 200%）。这里按你的要求关掉，用 16px 输入框、`clamp` 字号和响应式栅格来保证可读性。

## 十一、把本机数据同步回来

「同步」和「导入」是两件事：**导入是清空后覆盖，同步是按条目合并**。默认走同步。

### 能读哪些来源

- 应用「导出 JSON」生成的文件：`{app:"licai-jizhang", version:1, exportedAt, data:{...}}`
- 备份列表里单份「导出」生成的快照（同样带 `backupAt`）
- 直接就是 `{holdings, deposits, cash, settings}` 的裸数据
- 从别的设备、别的浏览器、旧的部署地址导出的同一个文件

不认识的 JSON 会当场拒绝并提示，不会写坏数据。

### 怎么判断新旧

每条记录带一个「改动时间」（`updatedAt`）：编辑持仓、买入卖出、改价、记分红、改定存都会刷新它。同步时按三步走：

1. **先按 id 配**：同一个 id 就是同一条记录。
2. **再按业务键配**：持仓看「类型 + 代码」，定存看「银行 + 产品 + 起存日」。这样两台设备各记一次同一只基金也能对上。（同一个业务键在本机出现多次时不猜，只按 id 配。）
3. **再比改动时间**：

| 情况 | 标记 | 默认选择 |
| --- | --- | --- |
| 内容完全一样 | 相同 | 跳过 |
| 来源更新 | 来源较新 | 用来源 |
| 本机更新 | 本机较新 | 保留本机 |
| 时间相同但内容不同 | 冲突 | 保留本机 |

**没有静默覆盖**：所有会变的记录都在预览里逐条列出（带「来源时间 / 本机时间」），每一条都能改选「用来源」还是「保留本机」，点「开始合并」才真正写入。

价格类字段（现价、净值日期、抓取来源）**不参与**内容比对——它们本来就该由行情刷新决定，不会因为两边价格不同就判成冲突。

### 合并前先备份

点「开始合并」的第一件事是强制存一份 `pre-sync` 快照（不受「内容相同就不存」的去重影响），合并完再存一份合并后的。合错了去「自动备份」里恢复即可。

### 现金和本机独有

- **现金**是单值，默认不动本机的。想用来源覆盖，勾上预览底部的「同时用来源的现金余额覆盖本机」。
- **本机有、来源没有**的记录原样保留，不会被删。

### 全程不联网

解析、比对、写入全部在本机内存里完成，没有任何网络请求，也不上传。文件是系统文件选择器读的，读完就结束。

### 和「整体覆盖」的关系

预览底部保留了「改用整体覆盖」：清空本机只留来源。老行为还在，只是不再默认。

## 十二、自动双向同步：能自动到哪一步

先说结论：**同一个网址的多个窗口全自动；跨设备只能做到「选一次 + 点一次」，中间不问你。**

### 同一个网址（多窗口 / 多标签页）——全自动

- `BroadcastChannel("licai-jizhang")` 为主，`storage` 事件兜底（老 Safari 没有 BroadcastChannel）。任何一次保存都会广播。
- 收到的窗口重读本机 `localStorage`（唯一真相），重绘概览、持仓、存款、备份列表，并提示「已同步其他窗口的改动」。
- **回声防护**：消息带 tabId，自己不处理自己的消息；再比一次内容指纹（持仓 + 存款 + 现金），一样就什么都不做。静止时零消息，不会互相刷。
- **心跳**：每 10 秒广播一次 hello，超过 25 秒没心跳的窗口从「其他窗口」计数里剔除，关标签页发 bye。设置卡片上的「其他窗口」就是这个数。
- **锁屏的窗口不重绘**，不会在锁屏后面偷偷渲染金额；解锁或切回前台时补一次。
- 切回前台（`visibilitychange`）也会对一次，防止后台期间漏掉的广播。

### 跨设备 / 跨来源——只能「点一次」

浏览器不给静态页面后台读写文件的权限，iOS Safari 尤其严格。所以能力边界是：

| 步骤 | 能不能自动 | 说明 |
| --- | --- | --- |
| 读入落点文件 | **不能** | 读文件必须由用户手势触发（点一下「选择同步落点」） |
| 合并判断 | 全自动 | 不需要逐条确认，按改动时间直接判 |
| 写回落点 | **不能** | 点「写回落点」下载到「文件」App，再覆盖原文件 |

- 选一次落点文件 → 立刻自动合并，被覆盖的那份进「版本留痕」，不需要你点头。
- 之后任何改动都会把设置卡片标成「待写回」，`写回落点` 按钮变成可点。
- 卡片里明写这两步，不会假装静默成功。

### 冲突怎么判

1. 内容完全一样 → 跳过。
2. 来源的改动时间更新 → 用来源（本机旧版进留痕）。
3. 本机的改动时间更新 → 保留本机（来源旧版进留痕）。
4. 时间相同但内容不同 → 保留本机，留痕里标注「时间相同，保留本机」。

**价格类字段不参与比对**（现价、净值日期、抓取来源、涨跌幅、万份收益）——行情本来就该由刷新决定，不会因为两边价格不同就判成冲突。

### 留痕能恢复

「版本留痕」最多 30 条，每条记着是谁的旧版、什么时候、完整 JSON。点「恢复」会先存一份 `pre-restore` 备份再写回；点「删除」只删留痕，不动账目。

### 全程不联网

测试里把 `jsonp` 和 `fetch` 换成抛错函数，跨窗口同步、自动合并、写回仍然全部成功（0 次网络调用）。文件是通过系统文件选择器读的，读完就结束。

### 做不到的

- **后台静默同步**：页面不在前台就没有定时器，也没有文件权限。
- **两个不同网址之间共享 localStorage**：同源策略不允许。`localhost` 和你的域名算两个源。
- **秒级实时跨设备**：需要服务器，本应用是纯前端。

### 本轮修掉的 8 个缺陷

1. **负零显示成 `-¥0.00`** —— `money()` 先判 `n < 0` 再取绝对值，`-0.001` 四舍五入后是 `-0.00`，看起来像欠钱。影响：所有金额、`signedMoney`、`pct` 的极小负值。改法：先按显示精度 `toFixed` 再判符号。
2. **银行名未转义** —— `<option value="` + 银行名 + `">` 直接拼接。银行名里带一个引号，`<option>` 就断了，选中项回落到第一项「工商银行」，**编辑定存会把银行名静默改掉**；带 `<` 的名字会被 HTML 解析器吞掉。改法：值、文本都过 `esc()`。
3. **记录 id 未转义** —— `data-id` / `data-hid` / `data-divid` / `data-trace` 都直接拼 id。导入的 id 含引号时属性被截断，实测后果：点「编辑」打开的是**新增**表单、点「删除」删不掉任何东西、买入 / 卖出 / 改价静默无效，并且能往页面注入任意属性。改法：`normalize` 里把 id 净化为 `[A-Za-z0-9_-]`（不合法就重新生成），插值处再 `esc()` 兜一层。
4. **负现金时资产分布合计 ≠ 总资产** —— 分布条只收正数项，负现金被整个丢掉。实测：基金 5,000 + 现金 −1,000，总资产显示 `¥4,000`，分布合计却是 `¥5,000`，图例还是 100%。改法：合计改成真实总资产，并注明「现金为负，未计入占比」（柱子没有负宽度，百分比只能按正数部分算）。
5. **撤销现金分红时现金被夹到 0** —— `applyDividend` 里 `state.cash = Math.max(0, cash + amt)`。记一笔 100 元现金分红、花掉、再删除这笔记录，现金应回到 −100，实际停在 0（少扣 100），与「已实现盈亏」对不上。改法：去掉 clamp，与 `normalize` 允许负现金的口径一致。
6. **示例数据缺字段** —— `loadDemo` 造出来的持仓没有 `divMode` / `dividends`、定存没有 `earlyRate` / `updatedAt`，与其他创建路径不一致；同步时这份数据的 `updatedAt` 是 0，永远输给任何来源。改法：补齐。
7. **到期提醒空态文案** —— 已到期的定存也会列出来（这是对的），但空列表时写的是「60 天内没有到期」，读起来像在说同一件事。改法：改成「没有临近到期或已到期的存款」。
8. **复利口径复核** —— 10 万 @2.35% 两年复利 = **4,755.23**（不是简单把 6,090 套过来：那是 3% 的数），10 万 @3% 两年 = **6,090.00**，三年 = **7,572.35**；单利 1,096 天 /365 = **7,056.44**、/360 = **7,154.44**。公式本身没错，是文档里混用了两个利率，已一并订正。

### 明确「没有」的东西

- **没有「负债」模块**。这个 App 记的全是资产端：基金 / 股票持仓、银行定期存款、借出去的款、现金余额；没有「我欠别人钱」、贷款、信用卡账单这类记账。（当时审计的「还款记录」指的是负债侧的还款计划，那一块确实不存在；资产侧的还款明细后来做进了「十六、借款」。）如果确实需要负债，得先定数据模型（本金 / 期数 / 还款方式 / 已还期数），再单独做一块，不属于修 bug 的范围。
- **删除没有撤销**。删除持仓、定存、分红都只有二次确认，没有 `Ctrl+Z`；能找回的路径只有「设置 → 自动备份」里的历史快照和「版本留痕」。这是有意的（纯前端不存操作日志），但要知道。
- **导出不含自动备份与留痕**。`payloadJSON()` 只带账本本体，备份快照和历史留痕留在本机；换设备时这两样不会跟着走。

## 十五、列表折叠：收起看摘要，点开看明细

持仓和定存列表里的每一条都是可折叠的，**默认收起**。

**收起时**（一行摘要 + 右侧箭头）：

| 列表 | 摘要里有什么 |
| --- | --- |
| 持仓 | 类型标签 · 名称 · 代码 · 市值 · 浮动盈亏与收益率 · 成本价 · 现价 · 净值日 / 行情日 · 份额 |
| 定存 | 银行 · 产品名 · 本金 · 状态（已计 / 已到期 / 提前支取）· 年利率 · 到期日 · 剩余天数 |

**点开**（点整条摘要任意位置）才展开完整明细和操作按钮：持仓是「持有份额 / 成本价 / 现价 / 持仓成本 / 已实现盈亏 / 日涨跌 / 分红方式 / 分红 / 流水」九项加「更新、买入、卖出、分红、改价、编辑、删除」七个按钮；定存是「年利率 / 起存日 / 到期日 / 期限 / 到期利息 / 天数」加进度条和「编辑、删除」。

几个实现上的选择：

- **状态存在单独的键 `licai_jizhang_ui_v1` 里**，不写进账本。所以折叠不会把账本标记成「有改动」，不会触发自动备份，不会进导出文件，也不会在多窗口之间同步——两台设备可以各自记各自的展开状态。
- **点开是就地改 `class`，不重新渲染整个列表**：不会跳滚动位置，长列表也不卡。
- **删除记录时会顺手清掉它的残留 id**（`pruneFold`），UI 键不会越用越大。
- **刷新、切换页签、重渲染都保持**：页签切换只切 `hidden`，状态在内存里；刷新从 localStorage 读。
- **键盘可用**：折叠头是 `role="button" tabindex="0"`，`Enter` 和空格都能开合。
- **窄屏不会被撑宽**：折叠头 `min-width:0`，摘要行 `flex-wrap:wrap` 且每段 `overflow-wrap:anywhere`，明细容器 `overflow:hidden`；长数字和长产品名都是换行而不是撑出横向滚动。
- **不影响编辑、删除与同步**：按钮仍在 `.fold` 里，展开后 `closest("[data-id]")` 仍然拿得到记录 id；折叠本身不调用 `save()`，内容指纹不变。这三点都有断言覆盖。
- 双击缩放的白名单里补了 `[data-fold]`，否则连续快速点两下折叠头，第二下会被「防双击放大」吞掉。
- **没有做「全部展开 / 全部收起」**：这次只要单条开合，多一个全局按钮就多一份状态要维护，先不加。

## 十六、借款（借出去的钱）

第五个页签「借款」记的是**别人欠你的钱**，和「存款」正好相反：存款是你把钱放银行，借款是你把钱放出去。

| 字段 | 说明 |
| --- | --- |
| 借款人 | 必填，最多 30 字 |
| 借款金额 | 借出的本金，必须 > 0 |
| 借款时间 | 不能晚于今天 |
| 借款期限 | 数值 + 单位（个月 / 年 / 天），到期日 = 借款时间加期限，月末不足取当月最后一天 |
| 借款利率 | 年化 %，0–36；填 0 表示不收利息 |
| 还款金额（本金） | 走「＋ 记一笔还款（本金）」入口：只记本金，必须 > 0，只有它冲减未还本金 |
| 已付利息 | 走「＋ 记一笔已付利息」入口：只记利息，不冲减本金，可以是 0，不能为负 |
| 还款时间 | 这笔款到账的日期 |

**「还款金额 / 已付利息 / 还款时间」不是借款上的三个字段，而是一张还款明细表**：一笔借款可以还很多次，每次单独记一行。
| 备注 | 选填 |

**利息怎么算**：单利，按「当时的未还本金」分段算到今天。

```
利息 = Σ（该段未还本金 × 年利率 × 该段天数 ÷ 计息基准）
```

举例：2026-01-01 借出 10 万、年利率 12%，2026-06-01 还了 1 万。到今天（2026-11-18）的应计利息 =
`100000 × 12% × 151 ÷ 365`（1/1–6/1）+ `90000 × 12% × 213 ÷ 365`（6/1–11/18）= **11,266.85 元**。还清之后本金段为 0，利息就停止增长。

**已付利息怎么参与计算**：

- 只有**本金部分**（还款金额 − 已付利息）冲减未还本金，所以「已付利息」填多了不会让欠款瞬间还清。
- 应计利息（按未还本金算到今天）减去**累计已付利息**，就是**未收利息**；本息合计 = 未还本金 + 未收利息。
- 举例：2026-01-01 借出 10 万、年利率 12%，2026-06-01 收到 2 万（其中利息 2,000）。到 2026-12-31：应计利息 10,706.63、已付利息 2,000、未还本金 82,000、未收利息 8,706.63、本息合计 90,706.63。
- **校验**：已付利息不能为负、不能大于还款金额；两条都在写库前拦住。
- **老数据**：以前没有这个字段的还款记录一律按 0 处理（等于「这笔还款全是本金」），`normalize` 还会把超过还款金额的脏值夹回，升级不会丢记录。
- **总资产口径**：总资产 = 持仓市值 + 定存本金 + **现金** + **借出未还本金** + **已收利息**。借款借出去时现金减少、借出增加，一头减一头加，所以「新增一笔借款」不会让总资产凭空多出一笔钱；收回本金是反向搬一次，同样不变；只有**已收利息**会让总资产变多。**未收利息**（还没收到）只做展示，不进任何合计。收益率的分母仍然只算成本 + 定存本金，不含借款。

几个刻意的口径：

- **不封顶**：借款不像定存会「到期」，逾期之后利息继续按同一利率累计，这样逾期越久欠得越多，符合常识。定存那边到期就停。
- **计息基准跟随「设置 → 计息口径」**（365 / 360），和定存保持一致，不同页面不会算出两个数。
- **未来日期的还款不计息**，早于借款日的还款也不倒算（`to = max(from, min(还款日, 今天))`）。
- **不动现金余额**：还了一笔不会自动给你加现金，也不会扣现金。现金是另一个字段，自己改；否则同一笔钱会被记两次。这条在页面上也写了。
- **还多了不算错**：还款总额超过本金时，摘要里会多一行「多收 ¥X」，未还本金停在 0，不出现负数。

**列表沿用持仓/定存那套折叠**：

- 收起：借款人 · 借款金额 · 未还本金 · 年利率 · 到期日 · 状态（剩余 N 天 / 逾期 N 天 / 已结清）
- 点开：上表全部字段 + 已还金额、未还本金、应计利息、本息合计 + 还款明细（每行带「撤销」）+ 「还款、编辑、删除」三个按钮
- 展开状态存在 `licai_jizhang_ui_v1` 的 `l` 数组里，和另外两个列表同一套机制，刷新 / 切页签 / 重开都保持

**到期提醒**：「概览 → 到期提醒」现在同时列定存和**未结清**的借款，按紧急程度排序；逾期显示「逾期 N 天」并标黄。已结清的借款不再出现在提醒里。

**计入总资产**：

- 概览只保留一项借款数字：**「已付利息」**——它是借款里各笔「已付利息」记录的合计（`state.loans[].repayments` 里 `kind === "interest"` 的和），和资产分布里的「利息」是**同一个数、同一份数据**，不另存一份；在借款里新增 / 修改 / 删除一笔已付利息，概览和分布同时变，刷新后还在
- 概览不出现借款的**其他**明细：没有借款统计格、没有借款卡片、没有空占位，顶部「应计利息」只算定存
- 资产分布里有「借出」和「利息」两段：借出 = 未还本金，利息 = 已收利息；两段加上基金 / 股票 / 定存 / 现金，合计正好等于总资产
- 「概览 → 到期提醒」照旧显示**借款人**和**应还金额**（未还本金 + 未收利息），外加到期日与年利率；已结清的不出现

**「存款 → 现金」与借款的资金流（第二十四轮）**：

- 存款页最上面新增一张「现金」卡片：显示 `state.cash`，右上「调整余额」直接改余额（可以是负数，说明现金花超了）。
- 借款和现金只有**一条**资金流，全部走 `cashDelta()`：
  - 新增借款 → 现金 −借款金额（钱借出去了）
  - 编辑借款金额 → 现金 −（新金额 − 旧金额），多借再扣、少借退回
  - 记一笔还款（本金）→ 现金 +还款金额
  - 撤销一笔本金还款 → 现金 −该金额
  - 删除借款 → 现金 +未还本金（这笔欠款不再记录，钱回到手上）
  - **利息一栏不动现金**：已收利息直接作为「利息」计入总资产，进现金就会和总资产里的利息算两次
- 旧数据迁移：老版本的借款借出去时没扣过现金，`normalize` 会在首次加载时把**未还本金**一次性从现金里扣掉，并弹一条提示「已把旧借款未还的本金 X 从现金余额里扣掉，总资产不变」。每条借款有 `cashBooked` 标记，只迁移一次，重载不会重复扣。
- 累计收益、收益率的分母都不含借款；借款页自己的统计（借出本金 / 已还本金 / 已付利息 / 实际收款 / 未还本金 / 未收利息 / 逾期）照旧

**备份 / 同步 / 留痕**：借款和其他记录走同一套。导出的 `data.loans[]`；同步按 `借款人 | 借款日 | 金额` 认身份，和 id 一起参与配对；只改还款备注不算内容变化（`repayments` 压成 `金额|日期|备注` 参与比对，`id` 和时间戳不参与）；被覆盖的一份照样进「版本留痕」，恢复时会分类回 `loans`。

**两个入口、一张记录只记一种钱**：借款详情里是**两个独立按钮**——「＋ 记一笔还款（本金）」和「＋ 记一笔已付利息」。点哪个就只开哪个弹窗，**弹窗里只有一个金额输入框**，从结构上就不可能把两笔钱混在一张记录里。

- 还款（本金）：标题「记一笔还款（本金） · v…」，字段只有金额 / 还款时间 / 备注；预览「将记为：还款本金 ¥8,000.00（未还本金剩 ¥92,000.00）」。
- 已付利息：标题「记一笔已付利息 · v…」，字段只有金额 / 收息时间 / 备注；预览「将记为：已付利息 ¥2,000.00（未收利息剩 ¥…）」。

两条记录各自成列表（「还款（本金）· N 笔」「已付利息 · M 笔」），每行都有自己的「改」和「撤销」，改一个不会动另一个。金额与未还本金一律只受本金记录影响，利息记录只累计已收利息；**实际收款 = 本金 + 利息**，在详情和总览分开显示。

**两个入口的最终标签与校验**：

| 入口 | 弹窗标题 | 唯一金额框的标签 | 校验 |
| --- | --- | --- | --- |
| 还款（本金） | 记一笔还款（本金） · v2026-11-18.24 | 还款金额（本金，元） | 必填；必须是数字；**必须大于 0**（0、空、负数、乱填都拦，停在弹窗里给红字 + 提示） |
| 已付利息 | 记一笔已付利息 · v2026-11-18.24 | 已付利息（元） | 留空按 0；必须是数字；**不能为负**；上限**没有**（利息可以大于本金，两栏互不约束）。填 0 也会存成一条**看得见、能删**的记录 |

**怎么确认打开的是最新版**：还款弹窗标题是「记一笔还款（本金） · v2026-11-18.24」/「记一笔已付利息 · v2026-11-18.24」，借款页标题旁、设置页底部也各有一个同样的构建号。**看不到这个构建号，就是旧副本**——iOS 从「文件」App 打开的旧 HTML 不会自动更新，要重新下载；装成 PWA 的把 App 从后台划掉重开一次（Service Worker 用的是 `skipWaiting` + `clients.claim`，重开即接管）。

**实际收款 = 本金 + 利息**：借款详情里「已还本金 / 已付利息 / 未还本金 / 未收利息 / 实际收款」五行分开列，总览统计里「借出未还本金 / 借款未收利息 / 借出已收利息 / 借出实际收款」四行也分开。未还本金**只按还款金额（本金）递减**，已收利息按利息栏累计，两者不互相冲抵。

**老数据迁移**：老版本的还款记录是 `{金额, 其中已付利息}`（金额含利息）。打开页面时自动搬成两栏——**本金 = 原金额 − 原已付利息**，利息原样搬到利息栏，所以「总金额」和「未还本金」的计算结果分毫不变；迁移会在启动时提示一次。整笔都是利息的老记录（本金算出来是 0）也会保留，不会丢。

**数字输入容错**：所有金额 / 利率 / 份额输入框都是 `type="text" inputmode="decimal"`（iPhone 上仍弹小数键盘）。这样「10,000」「１００００」「1 000」都能正常存成 `10000`；如果填了「一万」「abc」「1e3」这种解析不成数字的内容，会明确提示「XXX 填的不是数字」并停在弹窗里，**不会再被静默当成 0 保存**（`type="number"` 遇到这些字符会把 value 直接清成空，这是上一版「只改一栏另一栏被清掉」的根源）。

**还款金额必须大于 0，三道关都拦**：

1. 弹窗里 `validateRepayment()` 先算一遍，不合法就**行内红字 + toast 同时提示**，弹窗停在原地；
2. 数据层 `saveRepayment()` 再算一遍——全站**只有这一个函数**会 `repayments.push`，任何入口（新增、编辑、列表里的快捷还款）都绕不过去；
3. 导入 / 同步 / 恢复备份进来的记录如果金额 ≤ 0、负数或不是数字，`normalize` 直接丢掉，并在启动时提示「N 条还款记录的金额无效（必须大于 0），已忽略」。

**怎么确认你打开的是这一版**：设置页最下面有一行「版本 2026-11-18.14 · 数据只保存在这台设备」。看不到这一行，说明打开的是旧文件（iOS 从「文件」App 打开的旧副本不会自动更新，需要重新下载），或者 PWA 还在跑旧缓存（把 App 从后台划掉重开一次，让新 Service Worker 接管）。

**校验规则**（都在保存前拦，不写库）：

| 输入 | 拒绝条件 | 提示 |
| --- | --- | --- |
| 借款人 | 空 / 超 30 字 | 请填借款人名称 / 最多 30 个字 |
| 借款金额 | ≤ 0、非数字、> 1e12 | 借款金额需大于 0 / 过大，请检查 |
| 借款时间 | 格式不对 / 晚于今天 | 借款时间格式不对 / 不能晚于今天 |
| 借款期限 | ≤ 0 | 借款期限需大于 0 |
| 年利率 | 负数 / > 36 | 年利率不能为负数 / 不能超过 36% |
| 还款金额 / 已付利息 | 解析不成数字 | 还款金额 / 已付利息 填的不是数字 |
| 弹窗里并排两个金额框 | 一条记录同时带两个数 | 拆成两个入口：一张记录只有 `kind` + 一个 `amount`，本金和利息各自新增、各自编辑删除 |
| 还款金额 | ≤ 0 | 还款金额需大于 0 |
| 还款时间 | 早于借款时间 / 晚于今天 | 还款时间不能早于借款时间 … / 不能晚于今天 |

**明确没做的**：没有「利息自动转本金」（不算复利）、没有还款计划表（等额本息那种）、不提醒「该收款了」（只有到期日在提醒里出现）。这些属于新的产品设计，不是这次的范围。

## 十七、换设备 / 换网址怎么迁移数据

数据存在浏览器的 localStorage 里，**跟着网址走**：同一个域名+端口共用一份，换手机、换网址、清除 Safari 网站数据都会丢。

迁移步骤：

1. **旧设备**：设置 tab → 「导出备份」→ 得到一份 JSON 文件；或点「复制」拿到 JSON 文本
2. 通过 AirDrop / iCloud 云盘 / 微信传到新设备
3. **新设备**：Safari 打开同一个网址 → 设置 tab → 「导入备份」→ 粘贴 JSON 或选择文件 → 确认
4. 导入会**覆盖**当前数据，导入前先确认新设备上没有要保留的记录

注意：从 `xxx.github.io` 换到 `xxx.pages.dev` 就是两个不同的存储空间，数据不会自动跟过去，必须走一次导出/导入。**建议每月导出一次 JSON 存到 iCloud 云盘。**

## 十八、本地图标方案（不依赖托管）——结论与限制

你问的是：能不能不托管，直接在桌面放一个能用的图标。**结论：做不到可靠可用。**

**本次已经做进产品的部分：**

`index.html` 用 `file://` 打开时，会自己检测到 `location.protocol === "file:"`，在「设置 → 安装与离线」里如实显示：「当前用本地文件（file://）打开：记账、计息、导出都能用，但没有 Service Worker，也无法添加到主屏幕」。也就是说本地文件模式本身能用，只是没有图标、没有离线缓存。

**本次没能实测的部分（如实说明）：**

我尝试在真机上用「打开 URL」深链去打开 `file://` 路径来验证 iOS 的拦截行为，但设备当时不可达（Today App 不在前台），**没拿到真机结果**。所以下面三条是 iOS 平台的既有规则，不是本次实测结论：

1. Safari 地址栏不接受 `file://`；从「文件」App 点开 HTML 走的是快速预览（Quick Look），不是 Safari，没有「添加到主屏幕」入口。
2. 快捷指令的「打开 URL」只接受 http/https 等 scheme，`file://` 会被判为无效；「显示网页」动作是内置网页视图，不产生主屏幕图标，且存储是临时的，关掉即失效。
3. 因此「能装到桌面 + 数据能长期保存」只有 https 网址 + PWA 这一条路，也就是本方案。

## 十九、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 改了文件，手机上还是旧版 | Service Worker 走 network-first，正常刷新一次就会更新；没变化时到「设置 → 安装与离线」点「检查更新」，或删掉桌面图标重新添加 |
| 图标是灰块 / 问号 | `icons/` 没上传全，或大小写不一致（Linux 服务器区分大小写） |

## 二十一、还值得改进的地方

以下都是**这次没做**的，按我的推荐顺序排：

1. **先息后本的自动拆分**：现在「已付利息」要你自己算好填进去。如果加一个「按 LPR 先息后本」开关，勾上就自动把每笔还款拆成「利息 = 累计应计 − 已收，其余本金」，录还款只要填一个总额。
2. **还款计划表**：等额本息 / 等额本金 / 到期一次还本付息，生成每期应还金额与日期，点一下录入。现在的模型支持任意还款，但一期一期手输比较累。
3. **逾期提醒推到通知**：PWA 在 iOS 16.4 之后支持 Web Push，但**必须有服务器发推送**，纯静态站点做不到。所以现在只能在「打开 App 时」提醒，关闭状态下不会响。
4. **导出 CSV**：现在只有 JSON（给程序读的）。加一份「日期 / 类型 / 名称 / 金额 / 备注」的 CSV，方便扔进 Excel 或交给会计。
5. **记录级历史**：现在只有同步时的「版本留痕」，手动编辑不留痕。可以给每条记录存最近 N 次改动，误改能回退。
6. **借条照片 / 担保信息**：照片转 base64 会很快撑爆 localStorage 的 5 MB 上限，真要做得存到 IndexedDB，或者只存「文件已另存」的标记。
7. **利息收入个税**：民间借贷利息涉及个税，可以加一栏「已扣税」和「税后利息」。
8. **多币种**：现在只有人民币，汇率要手动维护，暂时不建议做。

### 逐项复查后**确认没问题**的部分

- 两个入口：新增 / 编辑 / 删除 / 列表分组 / 组标题笔数 / 汇总口径全部一致；编辑走的是同一条记录（`saveRepayment` 是全站唯一 `repayments.push`），**不会变成新增**；删除只删被点那条。
- 计算：未还本金只按本金递减；已收利息按利息记录累计；实际收款 = 本金 + 利息；应计利息按剩余本金分段、逾期继续计息、未来日期不计息、早于借款日不倒算；多收、结清、零利率都正确。
- 校验：本金 0 / 空 / 负数 / 乱填，利息负数 / 乱填，在**弹窗兜底与数据层**两处都拦；被拦时不写库、不关弹窗、行内红字与 toast 同时出现。
- 迁移：老结构 `{amount 含利息, interest}` 与中间结构 `{principal, interest}` 都拆成两条 `{kind, amount}`，拆完金额之和与未还本金分毫不变；整笔都是利息的记录保留；坏类型、坏日期、重复 id 都有兜底。
- 转义与 id：备注里的尖括号 / 引号 / 与号原样保存、显示时转义、编辑命中同一条；带 `&`、空格、重复的 id 被规范化去重后，改与删仍命中正确记录。
- 既有功能回归：持仓（平均成本、已实现盈亏、分红再投资）、定存（单利 / 复利 / 360 / 提前支取）、总资产与分布、列表折叠、导入导出、多窗口同步、离线缓存、到期提醒（含借款、按天数排序、逾期标签）全部正常。

### 仍然存在、这一轮**没有**改的

- 删除没有撤销（只有二次确认 + 备份 + 同步留痕能找回）。
- 导出只含账本，不含自动备份与版本留痕。
- 负债侧（借别人的钱）还没有模块，只有「借出去的钱」。
- 真实 iPhone 上的点按与捏合缩放仍未实测（本次执行环境连不上设备，点击走查在浏览器内核里完成）。

## 二十四、这一轮做的打磨（布局 / 精简 / 查 bug / 逻辑）

功能一个没删，只做收敛。四件事分开说。

### 1. 布局与样式

- **统计格改成「标签在左、金额在右」**：原来标签在上、金额在下，一格里两个数字对不齐；现在 `.stat` 是 `flex + space-between`，金额统一 `text-align:right`，再加上 `font-variant-numeric:tabular-nums`，一列数字的个位、小数点、千分位能竖直对齐，扫一眼就能比大小。
- **响应式两档**：`≥720px` 一行四格、阅读区 880px、卡片内边距 18/20px；`≤380px`（SE / 320px 宽）统计格与 `.kv` 都降到两列、整体收一号，长金额不再被截断。
- **圆角走变量**：`.stat` / `.item` 原来写死 `14px`，改成 `--r-sm`，跟 `--r` 一套刻度。
- **空账本有引导卡**：概览顶部新增一张「还没有任何记录」的卡片，说清从「持仓 / 存款 / 借款」哪个入口开始，并提醒导出备份；有任何一条记录就自动隐藏。

### 2. 精简代码

- 统计格原来在**四处各写一份** `[...].map(s => '<div class="stat">…')`（概览、分红、定存、借款），现在合并成 `statRow(label, value, cls, title)` + `paintStats(el, rows)` 两个函数，四处都调它；以后改样式只改一处。
- 另有 2 处手写统计格（分红卡、同步预览卡）也改走 `statRow`。
- 删掉没人用的 `.foot-note` 样式。
- 逐个核过 **150 个顶层函数**，全部有调用点，没有死函数；`type="number"` 仍是 0 处。

| 概览「已付利息」↔ 分布「利息」 | 同一份数据：都取 `totals().loanReceived`（`repayments` 里 `kind === "interest"` 的合计），增删改两处同步 |
| 总资产公式 | `市值 + 定存本金 + 现金 + 借出未还本金 + 已收利息`，四处口径一致（概览、分布、借款页、导出） |
| 现金 ↔ 借款联动 | 新增借款扣现金、编辑按差额、记本金还款加回、撤销与删除回退；利息不动现金 |
| 导入导出与老数据迁移 | 正常：`cashBooked` 缺失的旧借款一次性补扣未还本金并提示，重载不重复扣；坏 JSON / 类型不符 / 更高版本都会被挡在写库之前 |
| 多窗口同步 | 正常：`save()` 广播、`pullRemote()` 重读、内容指纹相同不重绘，折叠状态不参与比对 |
| 折叠展开 | 正常：默认收起、点开就地改 class 不重渲染、`pruneFold()` 清残留 |
| 空数据 | 三个列表都有 `.empty` 提示，概览加引导卡 |
| 搜索 / 筛选 | **当前版本没有搜索框**，列表只有折叠，这一轮没加（要的话下一轮补） |

### 4. 逻辑收敛

- 金额格式只有 `money()` / `signedMoney()` 两个出口，数字解析只有 `num()` / `numText()`（全角、千分位、空格都在这一层归一）。
- 还款校验只有 `validateRepayment(kind, amountRaw)` 一个口径，写库只有 `saveRepayment()` 一个入口。
- 借款金额、利息、未还本金只有 `loanCalc()` 一个计算口，汇总只有 `totals()` 一个出口，页面各处都从这里取值，不再自己 `reduce` 一遍。

## 二十五、净值能不能自动更新？（结论 + 批量录入）

**结论先说：能，而且早就已经在跑。**「持仓」页右上「刷新行情」、设置里的「自动刷新」，拉的都是真实接口，不是写死的假数据；收益 = 份额 × 最新净值 − 持仓成本，净值一变收益和收益率立刻跟着变。

### 为什么这个页面能跨域取数

因为它**不是用 `fetch`，而是用 JSONP**（`<script src>` 动态插入）。东财的接口响应头是 `content-type: text/plain`，**没有 `Access-Control-Allow-Origin`**——用 `fetch` 会被浏览器 CORS 直接拦掉，用 `<script>` 加载 JS 文件则不受同源策略约束，所以纯静态页面也能取到。

实测（2026-11-18 20:13，本机 curl）：

| 代码 | 最新净值日期 | 单位净值 |
| --- | --- | --- |
| 005455 建信睿丰纯债 | 2026-11-18 | 1.0726 |
| 002750 工银泰享三年 | 2026-11-18 | 1.0215 |
| 016778 长城收益宝货币C | 2026-11-18 | 万份收益口径 |

### 这套方案的边界（写在这里，免得以后踩）

- **第三方接口不是我们的**：`fundgz.1234567.com.cn` 已经 404 下线、`api.fund.eastmoney.com/f10/lsjz` 强制校验 Referer、`hq.sinajs.cn` 返回 403——历史上换过好几次。接口一旦挂了，应用会**保留上一次的有效值**并标「刷新失败」，不会把市值清零。
- **净值有发布时间**：基金要 19:00 之后才出当天净值，股票 09:30 前拿不到当天行情。所以「净值日期」按数据本身的日期显示，落后就标「今日净值未公布 / 落后 N 天」。
- **定开债基一个月才更一次**（005455 就是），不是没刷新，是本来就没有新数据。
- **货币基金**是「万份收益 + 净值恒为 1」，应用会自动识别，不会把万份收益当成净值。
- **银行定存**没有可跨域读取的公开接口，本金和利率仍然只能手动录入。

### 这一版补的：批量录入净值

一只一只改太慢，所以「持仓」页新增了 **「批量净值」**：

1. 点开，把「代码 净值」一行一条粘进去，空格、逗号、制表符都行，可以直接从天天基金或 Excel 整列复制；全角数字（`００５４５５　１.０８００`）、千分位（`1,450.00`）、行内日期（`2026-11-18`）都能认。
2. 第一次点「下一步」**只预览、不写库**：列出每只的「原价 → 新价」，把「账本里没有的代码」「认不出的行」单独标出来，按钮变成「确认写入 N 只」。
3. 再点一次才真正写入，只写匹配上的那 N 只；来源记为「手动」，净值日期用行内日期，没写就记今天。**认不出的行、对不上的代码一律不写，不会把你已有的净值改成 0。**
4. 写完 `priceAt` 会更新，列表里照样显示「手动 · 净值 2026-11-18」，自动刷新恢复后可以再覆盖。
